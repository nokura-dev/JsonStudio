# JsonStudio

JsonStudioは、JSONファイルを使ってテーブル定義とデータを管理・編集するツールです。表形式のデザイナーとJSONエディタを並べて、内容を確認・編集できます。

- **ローカルで完結：** 選択したフォルダのファイルを直接読み書きします。サーバーへのアップロードやデータベースへの接続は不要です。
- **柔軟なデータモデリング：** カラム構成・データ型・主キー・テーブル間の参照関係を自由に組み立て、実際のデータを確認しながらモデルを調整できます。
- **テーブル定義とデータの編集：** カラム・主キー・参照関係・初期値などの設定や、データの追加・変更・削除・並べ替えができます。編集内容は自動保存します。
- **JSONとCSVの相互変換：** CSVから新しいJSONファイルを生成したり、既存のJSONへデータを追加したりできます。JSONで管理するテーブル定義とデータをCSVへ出力することもできます。
- **DDL（SQL）の作成：** テーブル定義とデータからPostgreSQL用のSQLを生成し、コピー・保存できます。
- **ER図の作成：** テーブル間の関係を確認し、カラムのドラッグ＆ドロップで参照関係を追加・変更、参照線の選択とキー操作で削除できます。参照の編集はJSONへ自動保存され、カードの移動・サイズ変更、関係を考慮した自動整列、PNG出力もできます。

## 推奨ブラウザ

PC版の最新版Microsoft EdgeまたはGoogle Chromeを推奨します。ローカルファイルを直接読み書きするため、File System Access APIに対応したブラウザが必要です。フォルダを開く際は、読み取り・書き込みを許可してください。

ファイル操作が利用できない場合は、ブラウザを更新し、アクセス許可を確認してください。

## はじめに

GitHubで配布する`index.html`は、HTML・JavaScript・CSSを結合・ミニファイした単独HTMLファイルです。このファイルだけで利用でき、インストールやビルドは不要です。

1. GitHubで配布されている`index.html`をダウンロードし、ローカルPCに保存します。
2. Microsoft EdgeまたはGoogle Chromeで開きます。
3. 「フォルダを開く」で作業用フォルダを選び、読み取り・書き込みを許可します。

画面右上の丸枠の3本線メニューから「ヘルプ」を選ぶと操作説明を確認できます。「設定」は項目のみ表示し、現在は選択できません。配布版は`index.html`だけで動作するため、`js/`・`css/`フォルダを別途用意する必要はありません。

## 操作ガイド

### 1. フォルダを開く

1. DocumentsやDownloadsの中に作業用フォルダを作り、JSONファイルを置きます。例：`Documents/JsonStudio`
2. 「フォルダを開く」でそのフォルダを選び、読み取り・書き込みを許可します。
3. 左のファイル一覧から、編集するファイルを選びます。

フォルダを開けない場合は、DocumentsやDownloadsそのものではなく、その中の作業用フォルダを選び直し、ブラウザのアクセス許可を確認してください。

ファイルはローカルで読み書きします。サーバーへのアップロード機能はありません。別のフォルダを開き直したい場合は、再度フォルダを選択してください。

### 2. ファイル一覧・概要・ファイル操作

- 対象は選択フォルダ直下の `.json` ファイルです。サブフォルダ内と、名前がドットで始まるファイルは除きます。一覧では拡張子を省略します。
- 一覧の空白部分をクリックするとフォルダ概要に戻ります。テーブル数は対象ファイル数、カラム数は `cols`、レコード数は `data` の要素数の合計です。解析できないJSONのカラム数・レコード数は0件扱いです。
- 一覧右上の再読み込みボタンで、追加・変更・削除されたファイル一覧および内容を読み込み直せます。未保存の編集がある場合は先に保存し、保存できなければ再読み込みを中止します。
- 一覧を右クリックして「新しいJSONファイル」、ファイルを右クリックして「ファイル名変更」「ファイル削除」を選べます。拡張子は `.json` 固定です。新規作成後はそのファイルが自動的に選択されます。ファイル削除は確認後に実行し、バックアップは作成しません。
- 「新しいJSONファイルをCSVから生成」でローカルのCSVを選択できます。1行目をカラム名として、以降の先頭10件から日付・日時・真偽値・整数・小数・文字列の順に型を推定します。ヘッダーを含め10,000レコードを超えるCSVは処理を中断します。
- 「CSV解析結果」で左に元CSV、右に生成JSON、上部にカラム数とデータ件数を表示します。「JSONを保存して閉じる」で作業フォルダへ保存し、同名がある時は末尾に `_1`、`_2`…を付けます。「JSONを保存せずに閉じる」または右上の×で破棄できます。解析エラー時は保存ボタンが無効になります。

### 3. テーブル定義・データ編集

テーブル定義の「簡易／詳細」で表示項目を切り替えます。詳細では「NULL不可」「初期値」（デフォルト値）「コメント」も編集できます。

- 各セルを直接編集できます。「行追加」で追加、行末の「×」で削除、行番号のドラッグで並べ替えができます。
- データ型・参照テーブル・参照カラムは候補から選べます。候補以外も自由入力できます。参照テーブルの候補はファイル名、参照カラムの候補は指定先JSONの定義から表示します。
- テーブル定義の主キー・NULL不可を外すと、JSONからそのキーを削除します。「初期値」「参照テーブル」「参照カラム」「コメント」を空欄にした場合も同様です。
- テーブル定義やデータ編集を操作すると、エディタ内の対応箇所を薄い緑色で表示します。対象が画面外や折りたたみの中にある場合は、自動的に表示します。
- データにない項目は空欄で表示し、編集しなければ元の省略状態を維持します。行追加時はテーブル定義の初期値をそのまま反映し、初期値が未定義の列は空欄になります。空欄にすると該当キーを削除し、`null` の入力はNULL値、`"null"` の入力は文字列のnullになります。
- カラム名の変更はデータのキーにも反映します。テーブル定義の行を削除しても、データ内の対応するキーは保持します。

### 4. エディタ・保存

- 右側のエディタではJSON全体を編集できます。行番号横の三角で折りたたみでき、ファイルを開き直すと全て展開されます。「JSON整形」は空行を除き、空白4文字でインデントを整えます。
- **構文エラーの表示：** 入力が止まってから約200ms後にJSON全体を検査し、検出したエラー行の背景と行番号を薄い赤色で表示します。複数行のエラーを同時に表示し、表示対象は最大200行です。ファイルを開いたとき・切り替えたときは即時に検査し、修正後の検査でエラーがなくなると赤色表示を解除します。
- 折りたたみ内にエラーがある場合は、そのブロックの先頭行を薄い赤色で表示します。展開すると実際のエラー行を表示します。引用符や括弧の閉じ忘れなどでは後続行にも影響するため、表示された箇所を修正しながら確認してください。
- テーブルは行の外へフォーカスを移すと自動保存します。行追加・削除・並べ替えは即時保存します。エディタは領域の外をクリックすると自動保存します。変更がない場合は書き込みません。
- 「保存」または `⌘S`（Windowsは `Ctrl+S`）でも保存できます。変更がない時は保存ボタンが無効になります。

編集内容は選択したJSONファイルへ直接保存します。JSONに構文エラーがある場合は保存・整形できません。ステータスバーの通知も確認し、エラーを修正してから保存してください。

### 5. CSVを出力・読み込みする

「新しいJSONファイルをCSVから生成」は新規ファイルの作成、「データ編集」の「CSV読み込み」は選択中のファイルへのデータ追加に使います。

- テーブル定義の「CSV出力」は、行番号と現在の簡易／詳細モードの項目を出力します。削除ボタンの列は含めません。保存名は `テーブル定義(ファイル名).csv` です。
- データ編集の「CSV出力」は、表示中のカラム順・データ順で出力します。行番号・削除ボタンの列・定義にないキーは含めません。保存名は `データ編集(ファイル名).csv` です。
- どちらのCSV出力も、確認画面から全文コピーとファイル保存ができます。ファイルはExcelで日本語を判別しやすいUTF-8・BOM付き・CRLFです。括弧内のファイル名には元のJSONの拡張子を含めません。

1. データを追加するファイルを選び、データ編集の「CSV読み込み」でCSVを選択します。1行目のヘッダーをカラム名と完全一致で照合するため、CSVの列順は問いません。
2. 「CSV読み込み結果」の左で元CSV、右で追加予定のJSON、上部で追加件数を確認します。値は定義のデータ型で変換します。定義にない列は黄色で表示し、取り込みません。
3. 「データを取り込んで閉じる」で既存データの末尾へ追加して保存します。元のデータと未保存の編集も保持します。「データを取り込まずに閉じる」または右上の×でキャンセルできます。

CSVにないカラムには初期値をそのまま適用し、初期値もなければキーを省略します。CSVに列があって値が空欄の場合は初期値で置き換えず、文字列型なら空文字、数値・日付・真偽値型ならNULL値にします。引用符なしの `null` はNULL値、文字列型で引用符付きの `"null"` は文字列として読み込みます。

UTF-8・Shift_JIS・BOM付きUTF-16のCSVを読み込めます。ヘッダーを含め10,000レコードが上限です。型変換・列数・ヘッダーなどにエラーが1件でもあれば全件中止し、保存・取り込みボタンを無効にします。CSVを修正して読み込み直してください。

### 6. DDLを作成する

「DDL作成」で、現在のエディタ内容からテーブル削除・作成、コメント付与、データ挿入のSQLを生成します。物理テーブル名はJSONの `table`、テーブルのコメントは拡張子を除くファイル名を使います。主キー・外部キー・NULL不可・初期値・カラムコメントも反映します。

- 入力候補のデータ型に合わせて初期値を検査します。候補外の型では初期値の型検査を省略します。
- `serial` 型は主キーを設定してください。初期値は未設定または `null` のみ指定できます。シーケンス操作のSQLは生成しません。
- 初期値の `date` は `YYYY-MM-DD`、`datetime`／`timestamp` は `YYYY-MM-DD HH:mm:ss` 形式です。日時のT区切り・小数秒1〜6桁も使えます。この3型で `current_timestamp` を指定すると、各型にキャストして設定します。
- データの未定義項目はINSERT対象外、`null` はNULL、空文字は空文字として扱います。定義にないキーは警告付きで除外し、空の `{}` からはINSERTを生成しません。
- INSERTの型・NULL不可との不一致は警告にし、元の値をできる限り残してSQLを生成します。
- エラーは赤、警告は黄色で表示します。「クリップボードにコピー」または「ファイルに保存」でSQL全体を取り出せます。保存名は `DDL(ファイル名).sql`、保存形式はUTF-8・CRLFです。括弧内のファイル名には元のJSONの拡張子を含めません。
- JSON構文エラーなどでSQL自体を生成できなかった場合は、コピー・保存ボタンが無効になります。SQLが表示されていても、赤いエラーがある場合はJSONを修正して作成し直してください。

生成SQLにはテーブル削除が含まれます。実行前に内容を確認してください。

### 7. ER図を作成する

- 「ER図を作成」でフォルダ内のテーブルと参照関係を表示します。テーブル名は拡張子を除くJSONファイル名、主キーは「[PK]」で示します。参照先のテーブルまたはカラムが存在しない関係は赤い破線になります。
- **カードの移動・サイズ変更：** 見出しをドラッグすると移動、右下をドラッグするとサイズ変更できます。初期表示は先頭10カラムまでで、高さを広げると11番目以降も表示します。縮めると表示数が減り、収まらないカラムは末尾の「...」で示します。最低3カラム分の高さを確保し、続きがある場合は「...」の行も確保します。非表示カラムの参照線は「...」付近につながります。
- カード右下をダブルクリックすると、そのカードの幅と高さだけを初期サイズに戻し、位置は維持します。移動・サイズ変更は自動保存します。
- 「レイアウトをリセット」は、現在のカードサイズを維持したまま、参照関係を考慮して位置を自動整列・保存します。相互参照・循環参照をまとめ、カードの重なりや線の交差を減らす配置に調整します。
- **参照関係の追加・変更：** カラム名を掴み、別カードの参照先カラム名へドラッグ＆ドロップします。掴んだカラム名がカーソルに追従し、ドロップ先のカラムを緑色で強調します。ドラッグ元JSONの該当カラムに `reftable`（参照先のファイル名・拡張子なし）と `refcolumn`（参照先カラム名）を設定し、参照線を即座に描き直して自動保存します。
- 既に参照がある場合は、ドロップ先の情報で上書きし、線をつなぎ直します。同じカード内やカラム以外へのドロップ、操作のキャンセルでは変更しません。保存済みの同じ参照先へドロップした場合も変更せず、未保存の編集が残っている場合は保存を再試行します。
- **参照関係の削除：** 線をクリックすると太線で選択し、線以外の場所をクリックすると選択を解除します。選択中に `Backspace` または `Delete`（Del）を押すと、線を消し、参照元カラムの `reftable`・`refcolumn` をキーごと削除して即時保存します。同じ2つのカラム間で相互参照している場合は、両方のJSONから参照設定を削除・保存します。赤い破線の壊れた参照も同じ操作で削除できます。
- 「PNG出力」で図全体を `ER図(ファイル名).png` としてダウンロードできます。括弧内は選択中のファイル名（拡張子なし）で、ファイル未選択時はフォルダ名を使います。

参照関係の編集はテーブルのJSONファイルへ直接保存します。保存に失敗した場合は、ステータスバーに通知し、編集内容を未保存のまま保持します。対象のJSONファイルを一覧で選び、「保存」で再試行できます。

自動整列では参照元を左、参照先を右に配置します。関連のないグループは表示領域の縦横比に合わせて並べ、長い参照の連鎖は複数段に分けます。開くだけでは再整列せず、参照線をカードから迂回させる処理も行いません。

図が表示領域の横幅を超えた場合、横スクロールバーを常時表示します。カードの移動・サイズ変更、自動整列、モーダルの最大化などで横幅に収まると非表示になります。

### 8. 画面の幅・配置を変える

ステータスバー右端の「+」「−」で、アプリ全体を10%刻みで80%から120%まで拡大・縮小できます。中央に現在の倍率を表示します。倍率操作部分自体の大きさは変わりません。

ER図・SQL・CSV・ヘルプなどの共通モーダルは、タイトル部分のダブルクリックで最大化し、再度ダブルクリックすると初期サイズに戻ります。閉じて開き直した場合も初期サイズで表示します。

ナビゲーター・デザイナー・エディタの境界線をドラッグすると幅を変えられます。ダブルクリックでその境界線を初期位置に戻します。データ編集の列幅は必要に応じて10%刻みで最大50%まで縮めます。それでも収まらない場合は、テーブル下の横スクロールバーで確認できます。

境界線とER図の配置は、作業フォルダ内のドットで始まる設定ファイルへ自動保存します。同じフォルダを開くと復元され、設定ファイルは一覧・集計には含まれません。

### 9. 状態・エラーを確認する

画面下の「状態:」で未保存の変更や構文エラーを確認できます。「メッセージ:」は操作結果を10秒間表示し、状態が変わるとリセットされます。内容がない時は「---」になります。

CSV解析・保存エラーは確認画面内にも表示します。CSVの保存・取り込み中は操作ボタン・×・Escによる終了を無効にし、完了後に操作できるようになります。保存失敗時はアクセス許可などを確認し、同じ画面から再試行できます。

保存に失敗しても編集内容は残ります。構文やアクセス許可を確認して再度保存してください。他のアプリによる変更が検出された場合は、編集内容を控えてからフォルダを読み直してください。

| エディタ・デザイナーの領域移動監視 | `js/interactions.js` | — |
| JSON解析・検証・集計・整形 | `js/table.js` | — |

ローカルファイルとして開けるよう、JavaScriptは通常のscriptタグで読み込みます。`index.html`の読み込み順に従って`window.JsonStudio`へ各機能を登録し、最後に`base.js`が初期化します。テストも同じ読み込み順を使います。

編集内容は`state.editorDrafts`で保持し、`state.textFor(entry)`で未保存の内容を優先して参照します。保存済みテキストは`entry.text`に残し、外部アプリによる変更検出に使います。

通常保存とCSV追加保存は`base.js`の`persistEntry()`を共用します。書き込み成功後にだけ保存済みの解析結果を更新し、保存対象のドラフトを解除します。保存中に発生した別の編集は解除しません。

ボタンの通常の活性条件は`buttons.js`、処理中の一時ロックは`buttons.lock()`で管理します。一時ロックは元の活性・非活性を復元し、ダイアログを渡した場合は処理中のEsc終了も防止します。共通モーダルの操作ボタンは`disabled`を指定でき、省略時は活性です。SQLを生成できない場合の出力ボタンと、CSV解析エラー時の保存・取り込みボタンは非活性にし、クリック処理側にも実行防止のチェックを残しています。モーダルの操作ボタンはタイトルバー・メタデータと同じ共通配色を使います。

エディタとデザイナーは`state.setDraft()`で編集内容を更新します。保存済みの内容に戻った場合は未保存状態を解除します。デザイナーのJSON編集はDOMに依存しない`designer-document.js`にまとめ、`designer.js`は画面操作と自動保存の連携を担当します。空欄はキー削除、明示的な`null`はNULL値として扱い、行追加時は各カラムの`default`をJSONの値のままコピーします（0・false・空文字・nullも含む）。未定義のカラムはキーを作らず空欄にし、オブジェクトや配列の初期値は独立した値として複製します。

エディタの`revealLocation()`と`jsonLocations.rangeFor()`で、両テーブルの操作箇所をJSON内の行へ対応づけます。折りたたみ表示と保存するJSONは分けて保持し、スクロール時は表示レイヤーの位置だけを更新します。フォント・行高・余白は`css/editor.css`の変数にまとめています。

### SQL生成

DDLのダウンロード名は`DDL(ファイル名).sql`です。括弧内には元のJSONの拡張子を除いた名前を使います。

詳細モードの`not null`・`default`・`comment`は、それぞれNOT NULL・DEFAULT・COMMENT ON COLUMNに反映します。初期値は入力候補の型（serial・integer・float・varchar・boolean・numeric・date・datetime・timestamp、および対応する別名）に対して検査します。候補外の型では初期値の検査を省略し、PostgreSQL未対応の型そのものは従来通り定義エラーにします。

`float`は整数・小数・指数表記の有限な数値（数値形式の文字列も可）を許容し、空文字・真偽値・数値以外の文字列・NaN・Infinity・表現範囲外の値は初期値エラーにします。PostgreSQLの`float`をそのまま生成し、初期値はDEFAULTに反映します。`float(p)`も同じ検査を行い、pが1〜24の場合は単精度、それ以外の有効なpと省略時は倍精度として範囲を確認します。

日付の初期値は`YYYY-MM-DD`、日時は`YYYY-MM-DD HH:mm:ss`（T区切り・小数秒1〜6桁も可）に限定し、実在性も確認します。これらの型の`current_timestamp`は`CURRENT_TIMESTAMP::date`または`CURRENT_TIMESTAMP::timestamp`として生成します。numericの桁数は丸め後に判定します。serial型は主キーを必須とし、初期値は未定義またはnullのみ許容します。DEFAULTやsetval・nextvalなどの明示的なシーケンス操作は生成しません。[PostgreSQLの日時型](https://www.postgresql.org/docs/current/datatype-datetime.html)・[数値型](https://www.postgresql.org/docs/current/datatype-numeric.html)・[初期値](https://www.postgresql.org/docs/current/ddl-default.html)の仕様を参照しています。

定義の不備は赤いエラー、INSERTデータの不整合は黄色い警告です。INSERTは元の値をできる限り保ち、定義外のキーは除外します。空のオブジェクトからはINSERTを生成しません。警告が付いたSQLは、そのままデータベースで実行できるとは限りません。

データ編集テーブルが表示幅を超える場合、元の列幅を基準に90%・80%・70%・60%・50%の順で収まる段階を選びます。行番号と削除ボタンの列幅、文字サイズ、行の高さは維持します。50%でも収まらない時は横スクロールさせ、境界線のドラッグ・ウィンドウサイズ・表示倍率・カラム数の変更時に再計算します。

### CSV出力

テーブル定義のCSV出力は、行番号と現在の簡易／詳細モードで表示する項目を使います。項目の定義は`workspace.js`の画面描画と共有し、削除ボタンの列は含めません。未保存の編集も出力できます。

データ編集のCSV出力は、現在のカラム順とレコード順で出力し、行番号・削除ボタン・定義外のキーは含めません。簡易／詳細モードには依存しません。未定義の項目は空文字、明示的なnullは引用なしの`null`として区別し、空のオブジェクトも表示中の1レコードとして出力します。データが0件の場合はヘッダーのみを出力し、カラムが0件の場合はCSV出力ボタンを無効にします。

ヘッダーは全項目をダブルクォートで囲みます。データでは文字列を引用し、行番号・数値・真偽値・明示的なnullは引用しません。未定義のテキスト項目は空文字、チェックボックスはtrue／falseで出力します。カンマ・改行・ダブルクォートのエスケープは[RFC 4180](https://www.rfc-editor.org/rfc/rfc4180)に従います。フィールド内の改行は引用の内側に保持するため、1レコードが複数の物理行にまたがる場合があります。

モーダルはDDLと同じ文字サイズ・行番号・横スクロールで表示し、CSVの文字列や数値を色分けします。コピーにはプレビューの行番号を含めず、出力対象のCSV全文を渡します。保存名は`テーブル定義(ファイル名).csv`または`データ編集(ファイル名).csv`です（括弧内は元のJSONの拡張子を除いた名前）。テーブル定義・データ編集のどちらも、Excelで文字コードを判別できるようUTF-8（BOM付き、先頭バイトはEF BB BF）・CRLFでダウンロードします。BOMはファイル保存時だけ付与するため、プレビューとコピーには含めません。コピーとテキスト保存の処理はDDLと共通で、BOMはCSVの保存時だけ指定します。[Microsoftの案内](https://support.microsoft.com/en-gb/excel/opening-csv-utf-8-files-correctly-in-excel)を参照しています。

### ファイル作成

新規JSONファイルの作成後は一覧を更新し、そのファイルを選択してデザイナーとエディタを表示します。

「＋ 新しいJSONファイルをCSVから生成」でローカルのCSVを選び、既存の共通モーダルで元CSVと生成JSONを左右に確認できます。上部にはカラム数・データ件数・保存予定名を表示し、保存して閉じる／保存せずに閉じる／右上の×を使用します。解析や保存に失敗した場合はモーダル内にエラーを表示し、保存失敗後は再試行できます。

1レコード目のヘッダーから`cols[].column`を作り、先頭10データレコードからdate → datetime → boolean → integer → float → stringの順で型を推定します。ヘッダーを含む10,000レコードが上限です（引用符内の改行はレコードを増やしません）。重複・空欄のヘッダー、不正な引用符、列数不一致、推定後の型に変換できないデータはエラーです。

日付はハイフン・スラッシュ・ドット・年月日・8桁表記、昭和・平成・令和の和暦を扱い、日時はコロン・時分秒・午前午後・AM/PMなどに対応します。JSONの日付は`YYYY-MM-DD`、日時は`YYYY-MM-DD HH:mm:ss`（小数秒は保持）へ正規化します。真偽値はy/n・true/false・0/1・はい/いいえなどを認識します。数値は全角や正しい3桁区切りにも対応します。空欄は文字列列では空文字、それ以外ではnullです。囲み引用符を除去して二重引用符を復元し、引用なしのnullはNULL値、引用付きの"null"は文字列として区別します。

読み込みはUTF-8を優先し、UTF-16のBOMとShift_JISにも対応します。保存名はCSVの拡張子を除いた名前＋`.json`で、既存ファイル・フォルダとの大文字小文字を無視した重複には`_1`・`_2`…を付けます。保存直前にも重複を確認し、`table`には最終的なJSONファイル名の拡張子を除いた名前を設定します。保存成功後は新規ファイルを選択します。保存は既存のFile System Access APIと安全な書き込み・失敗時の作成途中ファイルの削除を共用します。

### データ編集へのCSV読み込み

「CSV読み込み」は選択中のJSONの`cols`を使い、CSVヘッダーとカラム名を完全一致で照合します。カラム順は問いません。値は定義のデータ型で変換し、日付・日時の国内表記や真偽値などは新規JSON生成と同じ変換を使います。未知の型は文字列のまま保持します。

CSVにないカラムには定義の`default`を行追加と同様にそのまま適用し、初期値もなければキーを省略します。CSVに列があり値が空欄の場合は、文字列型なら空文字、それ以外の対応する型ならnullとし、初期値で置き換えません。引用符なしの`null`は明示的なnullです。

既存の共通モーダル「CSV読み込み結果」に、左はCSVの表、右は追加予定の`data`をシンタックスハイライト付きで表示します。定義外のCSV列はヘッダーと各セルを黄色で表示し、取り込みから除外します。型変換・列数・ヘッダーなどのエラーは全件取り込み中止として表示します。

「データを取り込んで閉じる」で既存`data`末尾へ追加して直接保存します。未保存の編集内容も保持して一緒に保存します。キャンセルではファイルと編集内容を変更しません。解析後の取り込み先変更や外部でのファイル変更は検出して中止し、保存失敗時も追加前の状態を保って再試行できます。データ0件では書き込みません。文字コードと10,000レコードの上限は新規JSON生成と共通です。

### 単独HTML版

開発環境では、HTML・JavaScript・CSSを結合してミニファイした単独HTMLを`neu/dist/index.html`として生成します。出力先フォルダがなければ作成します。GitHubで配布する際は、生成物をそのまま`index.html`として公開します。プロジェクト直下の旧`index.min.html`は更新しません。

ミニファイ完了後、プロジェクト直下の`README.md`も`neu/dist/README.md`へ内容を変更せずにコピーします。既存のコピーがある場合は上書きします。この処理は`tools/build_minified.py`に含まれます。

利用者から次のミニファイ依頼があるまで、このファイルは更新しません。通常の修正は`index.html`・`js/`・`css/`に行い、自動ビルドの対象には含めません。

明示的な再生成依頼があった場合のみ、次の手順を実行します。

```sh
python3 -m pip install --target /private/tmp/jsonstudio-minify-deps -r tools/requirements-minify.txt
PYTHONPATH=/private/tmp/jsonstudio-minify-deps python3 tools/build_minified.py
```

生成後、`neu/dist/index.html`を公開用フォルダへコピーします。開発用の`index.html`はそのまま保持します。ミニファイのみの依頼では`neu/resources/index.html`や実行ファイルは更新しません。`neu build --clean`で生成物が削除された場合は、必要に応じて再生成します。
